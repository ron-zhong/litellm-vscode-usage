# Plan v1.0.3 — UI polish, force-refresh, and month-to-date dashboard bar chart

Status: **Finalized — implementing.** All clarifications resolved with the user.
Target version: `1.0.3`.

---

## 1. Background

`versions/v1.0.2_REVIEW.md` raised five UI/behavior points, plus a sixth request
for dashboard spend history. This plan implements all of them conservatively,
keeping the v1.0.2 throttle/single-flight architecture intact.

## 2. Resolved decisions (from user)

- **Q-A:** Drop **API Base** and **Data Source** from pop-up *and* dashboard.
- **Q-B:** Label is **"User Alias"** (in code; "Alais" = typo). Kept in both.
- **Point-2 / C3:** Only the explicit **Refresh** command force-reloads the
  **current spend** (`/v2/user/info`). It does **not** refresh dashboard logs.
  Periodic timer / status-bar click / dashboard open stay cache + cooldown driven.
- **`budgetDuration`:** kept in `BudgetInfo` + API response; not rendered.
- **C1:** Use **`/spend/logs?summarize=true`** (Option A). Show the **month-to-date**
  data as a **vertical bar chart** (spend per day; no monthly table).
- **Admin switch:** a **build-time** constant `DASHBOARD_BREAKDOWN_ENABLED`
  (default `true`) lets the system admin turn the breakdown (and its
  `/spend/logs` call) off when packaging the extension. When `false`, the
  dashboard shows the budget summary only — no logs call.
- **C2 / daily cache:** once the month-to-date usage is loaded, **do not load it again
  until the next calendar day** (success caches for the day; a failure does not
  cache, so the next open can retry).

## 3. `/spend/logs?summarize=true` contract (verified from LiteLLM source)

- Returns an array of one object per day: `{"startTime":"YYYY-MM-DD",
  "spend":<number>, "users":{...}, "models":{...}}`, zero-padded for missing
  days, sorted ascending. **No `total_tokens`** → bar chart is spend-only.
- Date params are `YYYY-MM-DD`; the `end_date` filter is `<= midnight UTC`, so
  we pass `end = today + 1 day` to capture all of today, then locally trim to a
  clean month-to-date window (1st of current month → today), 0-filled, oldest → newest.
- Endpoint is deprecated but the summarized payload is tiny (~30 rows) and is
  fetched at most once per user per day → negligible load.

## 4. Proposed changes (by file)

### `src/litellmClient.ts`
- Keep `fetchBudgetInfo` + `BudgetInfo` unchanged.
- Add date helpers: `todayUtcStr()`, `daysAgoStr(n)`, `addDayStr(dateStr, n)`.
- Add `SummarizedDay = { date: string; spend: number }` and `DailyPoint = { date: string; spend: number }`.
- Add `fetchSpendLogsSummarized(apiBase, apiKey, startDate, endDate)` →
  `GET /spend/logs?start_date=…&end_date=…&summarize=true`, returns
  `SummarizedDay[]` (normalizes `startTime` → `date`, reads `spend`).
- Add `buildDailySeries(days, todayStr, windowDays = 30)` → `DailyPoint[]`:
  30 calendar days `today-29..today`, 0-filled, **oldest → newest**. Pure/unit-testable.

### `src/constants.ts`
- Add `DASHBOARD_BREAKDOWN_ENABLED = true` (admin build-time switch; document).
- Add `DASHBOARD_BREAKDOWN_DAYS = 30`.

### `src/extension.ts`
- `resolveSoftBudgetStyle()` default: `$(radio-tower)` → **`$(graph)`**.
- `litellm.refresh`: call `controller.refresh({ force: true })` (budget only);
  drop the cooldown/"next refresh in Ns" gating; do **not** touch logs.
- `showSpendDetails()` pop-up: remove `Budget Window`, `Data Source`, `API Base`
  rows. Keep Current Budget Spend, Budget Limit (if maxBudget), Budget Used + bar
  (if maxBudget), Resets At (if resetAt), User Alias (if alias).
- New dashboard-logs daily cache + single-flight:
  - state: `logsCache: DailyPoint[] | undefined`, `logsFetchDate: string | undefined`, `logsInFlight`.
  - `ensureDailySpend(conn)`:
    - if `!DASHBOARD_BREAKDOWN_ENABLED` → return `undefined` (no call).
    - if `logsFetchDate === todayUtcStr() && logsCache` → return cache (no call).
    - if `logsInFlight` → return it (single-flight).
    - else fetch `fetchSpendLogsSummarized(start=today-29, end=today+1)`,
      `buildDailySeries`, on success set `logsCache` + `logsFetchDate = today`
      (no re-fetch today); on failure return `undefined` (no cache/date → retry
      allowed on next open).
- `litellm.showUsage`: `controller.refresh()` (budget, gated) → info;
  `ensureDailySpend(conn)` → dailySeries (may be undefined); open panel with
  info + dailySeries. A logs failure does not block the dashboard.
- `onResult(info)`: still calls `UsagePanel.currentPanel?.update(info)`; the
  panel keeps its existing dailySeries and only refreshes the budget part.

### `src/usagePanel.ts`
- Cards: Current Budget Spend, Budget Limit (only if maxBudget), Budget Used
  (only if maxBudget), Resets At. Remove Budget Duration card. Hide Budget
  Limit/Used entirely (not "—") when no budget (review point 3).
- Details table: Current Budget Spend, Budget Limit (if maxBudget), Budget Used
  (if maxBudget), Budget Resets At, User Alias. Remove Budget Duration, API
  Base, Data Source rows.
- **New "Month-to-Date Spend" section** (only when a daily series is provided):
  - A CSS vertical bar chart, no JS (`enableScripts:false`): bars for each day of the current month, height ∝
    `spend / maxSpend`, `--vscode-charts-blue` fill, `title` tooltip per bar
    (`YYYY-MM-DD: $x.xx`), sparse x-axis labels (day-of-month every ~5 days).
  - Header line + total MTD spend + max-day value.
  - Orientation: **oldest → newest, left → right** (latest day on the right) —
    standard time-series; flippable if preferred.
- `createOrShow(info, dailySeries, apiBase, productName)`; `update(info)`
  re-renders budget with the stored dailySeries. No API calls from the panel.

## 5. Load profile

- Budget (`/v2/user/info`): unchanged from v1.0.2 — ~1 call/user/refresh interval;
  force-refresh only on explicit Refresh; never logs.
- Logs (`/spend/logs?summarize=true`): **only** on dashboard open, **at most once
  per calendar day per user** (daily cache + single-flight), tiny payload, and
  fully removable via the admin build-time switch. 200 users → ≤200 small calls/day.

## 7. Risks / notes
- `/spend/logs` is deprecated; we use the tiny `summarize=true` payload, fetched
  ≤1×/day/user, and disable-able via the admin switch — conservative.
- `summarize=true` `startTime` may serialize as `YYYY-MM-DD` or ISO; parser uses
  `slice(0,10)` to handle both. Extra per-row keys (`users`, `models`, api-key
  sums) are ignored.
- If the proxy has no DB / endpoint errors, the dashboard still shows the budget
  summary with a "month-to-date breakdown unavailable" note.
- Bar-chart orientation is chronological (latest on right); say the word to flip.
