## 2) Manual Refresh force-reload (budget only) — src/extension.ts
- `litellm.refresh` now calls `controller.refresh({ force: true })` and drops the
  cooldown/"next refresh in Ns" gating. Success → "usage refreshed."; failure →
  a light confirmation message (the error is already rendered/toasted via `onError`).
- It refreshes the **budget only** (`/v2/user/info`). It does **not** touch the
  dashboard month-to-date logs (per the user's C3 answer). The budget controller's
  single-flight still dedupes concurrent Refresh clicks.

## 4) Dashboard trimmed + hide-no-budget — src/usagePanel.ts

## 5) Dashboard month-to-date bar chart — src/usagePanel.ts + src/litellmClient.ts
- New "Month-to-Date Spend" section: a CSS vertical bar chart (no JS;
  `enableScripts:false`). Bars for each day of the current month, height ∝ `spend / maxSpend`, themed with
  `--vscode-charts-blue`, a `title` tooltip per bar (`YYYY-MM-DD: $x.xx`), sparse
  x-axis labels (day-of-month every 5 days), total + peak-day summary. Orientation
  oldest → newest (latest on the right).
- `src/litellmClient.ts` additions (verified against the LiteLLM source for
  `/spend/logs?summarize=true`):
  - Date helpers: `todayUtcStr()`, `daysAgoStr(n)`, `addDayStr(dateStr, n)`.
  - `SummarizedDay` / `DailyPoint` types.
  - `fetchSpendLogsSummarized(apiBase, apiKey, startDate, endDate)` →
    `GET /spend/logs?start_date=…&end_date=…&summarize=true`; normalizes
    `startTime` (handles `YYYY-MM-DD` or ISO) → `date`, reads `spend`, ignores
    extra per-row keys (`users`, `models`, api-key sums).
  - `buildDailySeries(days, startStr, endStr)` → month-to-date calendar days
    (1st of current month → today), 0-filled, oldest → newest. Pure/unit-testable.

## 6) Daily cache + single-flight for dashboard logs — src/extension.ts
- State: `logsCache`, `logsFetchDate` (YYYY-MM-DD), `logsInFlight`.
- `ensureDailySpend()`:
  - returns `undefined` immediately when `DASHBOARD_BREAKDOWN_ENABLED` is false;
  - returns the cache when `logsFetchDate === today` (no re-fetch until next day);
  - single-flights concurrent opens;
  - fetches `start = 1st of current month`, `end = today+1` (so the API's `<= midnight UTC`
    end filter captures all of today), builds the month-to-date series, and on success
    sets `logsCache` + `logsFetchDate = today`;
  - on failure returns `undefined` without caching/setting the date, so the next
    open can retry.
- Called only from `litellm.showUsage` (dashboard open). Never from the periodic
  timer or the Refresh command. `onResult` keeps an open dashboard's budget part
  fresh (via `update(info)`) while the chart stays daily-cached.

## 7) Build-time admin switch — src/constants.ts

## API-call budget

- Budget (`/v2/user/info`): unchanged from v1.0.2 — ~1 call/user/refresh interval;
  force-reload only on explicit Refresh.
- Logs (`/spend/logs?summarize=true`): **only** on dashboard open, **at most once
  per calendar day per user** (daily cache + single-flight), tiny payload (~30
  rows), and fully removable via `DASHBOARD_BREAKDOWN_ENABLED`. Worst case 200
  users → ≤200 small calls/day, independent of the periodic budget load.

## Risks / notes
- `/spend/logs` is deprecated; we use the tiny `summarize=true` payload, ≤1×/day/user,
  disable-able via the admin switch — conservative.
- The `summarize=true` `startTime` may be `YYYY-MM-DD` or ISO; the parser uses
  `slice(0,10)` to handle both. Extra per-row keys are ignored.
- If the proxy has no DB or the endpoint errors, the dashboard still shows the
  budget summary with a "month-to-date breakdown unavailable" note.
- Bar-chart orientation is chronological (latest on right); flippable on request.
- Manual Refresh no longer surfaces a "next refresh in Ns" message because it now
  always force-reloads the budget (the dashboard chart is intentionally excluded).
